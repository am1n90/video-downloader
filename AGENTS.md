# Video Downloader — память проекта

Прочитай этот файл перед началом работы. Здесь всё состояние проекта.

## Что это

Десктопный загрузчик видео/аудио (YouTube, VK, TikTok и др.): Fluent Design,
очередь с паузой/докачкой, библиотека, автообновление через GitHub Releases.
С 15.09.2026 идёт большая задача «Торрент-стриминг» (раздел ниже).
Пользователь — владелец репозитория am1n90. Язык общения — русский.

## Как продолжить (сводка на 16.09.2026, для новой сессии и другой машины)

Здесь всё, что нужно, чтобы продолжить без пересказа владельца. Подробности
— в разделе «Торрент-стриминг», «Архитектура», «История» и в
`.vd-proto\torrent\RESULTS.md` (он в git).

### Окружение на другой машине (офисная — ГОТОВА 16.09.2026)

1. Python 3.13 per-user — команда в разделе «Торрент-стриминг» →
   «Офисная машина».
2. `pull.bat`, затем `build.bat` (создаст build-venv на 3.13 и поставит
   requirements вместе с libtorrent). Если сборка не нужна, достаточно:
   `py -3.13 -m venv build-venv` и
   `build-venv\Scripts\pip install -r requirements.txt -r requirements-dev.txt`.
3. Запуск тестов: `PYTHONIOENCODING=utf-8`, GUI-тесты дополнительно с
   `QT_QPA_PLATFORM=offscreen`, например:
   `build-venv\Scripts\python.exe .vd-tests\test_torrent_engine.py`
   (тест сам поднимает сид на 127.0.0.1, интернет не нужен).
4. Прототип Этапа 0 (если понадобится сверить цифры) —
   `.vd-proto\torrent\README_PROTO.md`; тестовые видео пересоздаёт
   `make_media.py`. Настоящий рой — только на домашней машине.

### Сессия 1.3 — сделано (все 8 пунктов плана)

1. Один движок на приложение, в `MainWindow` рядом с `DownloadManager`;
   колбэки из фонового потока идут в GUI через отдельный `Bridge`.
2. Добавление magnet-ссылкой и `.torrent`-файлом; до метаданных
   состояние `metadata` — «Получение сведений о раздаче…».
3. Дерево файлов с галочками (`TorrentFilesDialog`): галочка папки
   ставит/снимает вложенные, родитель сам становится частично
   отмеченным; пользователю показывается `selected_size`. Снять всё
   нельзя — «Применить» блокируется (иначе раздача просто встанет).
4. Карточки: прогресс, объём, скорость, ETA, пиры, индикатор раздачи;
   при `error` — текст и имя файла + «Повторить» (`engine.retry()`).
   Кнопки пересоздаются только при СМЕНЕ состояния (снимки — 2 раза в с).
5. Удаление — `ConfirmRemoveTorrentDialog` с галочкой «удалить файлы».
6. Настройки, группа «Torrent»: папка, раздача после скачивания
   (доходит до живого движка сигналом), порт.
7. `closeEvent` — `engine.shutdown(timeout=3.0)`.
8. Тесты: `test_torrent_gui.py` 52 PASS (offscreen, локальный сид,
   ожидание `processEvents + sleep`) и живая проверка на настоящем окне.

**Решение по ленивому старту движка (отход от буквы плана).** Движок
СОЗДАЁТСЯ в `MainWindow`, но `start()` зовёт сама страница в `showEvent`.
Причина: сессия libtorrent занимает порт и вызывает системный запрос
брандмауэра (находка Этапа 0.1), а тем, кто торрентами не пользуется,
это ни к чему при каждом запуске. `start()` идемпотентен; раздачи из
fastresume поднимаются при первом входе в режим. Проверено живой
проверкой: до показа страницы `_ses is None`, после — сессия есть.

### Открытые вопросы и что не проверено

- Движок и GUI на настоящем рое (автотесты и живая проверка — только

- Порт в Настройках применяется только с перезапуском (сессия libtorrent
  создаётся один раз) — это написано в подписи карточки; менять порт на
  живой сессии не пробовали.
- `build.bat` с libtorrent (`--collect-all` + проверка DLL) и
  установленная копия — шаг 1.4; там же `[InstallDelete]` на
  `{app}\_internal` (находка 6).
- Нехватка места на диске при скачивании раздачи.
- Нужно ли снижать `min_reconnect_time` для стриминга (Этап 2, находка 18)
  и важны ли входящие соединения для стриминга (находка 13).
- Офисная машина: Python 3.13, сборка и офлайн-регресс сделаны 16.09.2026
  (см. «Историю»); настоящий рой там по-прежнему не проверяется.
- П.15 «Что осталось» (force_foreground разворачивает окно) — не
  исправлено по решению владельца.

## Сборка (build.bat)

build-venv (пересоздаётся) → requirements.txt + requirements-dev.txt →
PyInstaller `--noconsole --onedir --collect-all qfluentwidgets
--collect-all yt_dlp` → build_ffmpeg.ps1 (BtbN win64-gpl, кэш в
build-ffmpeg-cache/) → тестовый запуск `-selftest` (авто-выход) →
set_version.ps1 (версия в installer.iss) → ISCC (Inno Setup 6) →
build_manifest.ps1 → Output\latest.json (version/url/sha256).

Результат: `Output\VideoDownloader-Setup-<ver>.exe` + `Output\latest.json`.

## Установщик (installer.iss)

Per-user (`PrivilegesRequired=lowest`), `{localappdata}\Programs\
VideoDownloader`, без UAC, AppId фиксированный, RU/EN, ярлыки
Пуск+рабочий стол, PATH не трогается (ffmpeg — через `ffmpeg_location`
при sys.frozen), данные пользователя при деинсталляции сохраняются
(интерактивный вопрос; в /VERYSILENT — всегда).

## Автообновление

- Манифест: `releases/latest/download/latest.json` (стабильный алиас)
- Схема: автопроверка при старте (2.5с, ключ check_updates) или кнопка →
  InfoBar «Доступна версия X» → подтверждение → скачивание с прогрессом и
  отменой в %TEMP% → SHA-256 → тихая установка → перезапуск (через
  [Run]+Check:LaunchAfterUpdate); офлайн → «Не удалось проверить
  обновления» (не «нет обновлений»)
- SHA-256 = целостность, НЕ подпись (см. README_BUILD.md)

## Правила работы

- Работать только внутри папки проекта. Вне её разрешено только:
  %LOCALAPPDATA%\VideoDownloader и %LOCALAPPDATA%\Programs\
  VideoDownloader (с backup перед изменением) и %TEMP% (удалять после
  себя). Любое другое место на диске — сначала спросить владельца.
  Разрешено дополнительно (15.09.2026): %LOCALAPPDATA%\Programs\
  Python\Python313 (установка Python 3.13 для сборки)
- НИЧЕГО не публиковать на GitHub (push, release) без явного
  подтверждения владельца
- downloader.py (логика загрузок) не трогать без явной задачи владельца
- Новые зависимости: только stdlib в рантайме; сборочные — в
  requirements-dev.txt. Согласованные исключения: curl_cffi (1.0.4),
  libtorrent (торрент-стриминг, 15.09.2026)
- Bump версии = правка APP_VERSION в config.py (одно место), build.bat
  разнесёт в installer.iss (set_version.ps1) и latest.json
- settings.json — личные данные владельца: не коммитить, не пушить,
  не показывать содержимое
- SmartScreen-предупреждения при установке — ожидаемое поведение
  (нет кодовой подписи), это не баг
- Релизы: тег v<ver> строго равен APP_VERSION; порядок: коммит →
  push в main → gh release create v<ver> --target main; latest.json
  загружается вместе с установщиком
- Если задача неоднозначна — выбрать разумное допущение и явно
  написать его в отчёте; правила молча не придумывать
- В конце каждого отчёта — отдельный список «Что не проверено»
- Команды для этой машины — под фактическую оболочку терминала Cline
  (сейчас Git Bash/MINGW64; проверять uname -s), одной строкой; gh при
  необходимости по полному пути. Многострочный текст (коммиты, notes
  релиза) передавать файлом UTF-8 без BOM во временной папке вне
  репозитория
- Не ломай работающее: не переписывать несвязанный код, не создавать
  второй механизм там, где уже есть рабочий, сохранять совместимость
  settings.json и истории загрузок
- Ищи корневую причину проблемы: изучить текущую реализацию и поток
  данных; временные обходы без понимания причины не допускаются
- Файлы писать только инструментом редактирования, не через echo/Python
  в bash — экранирование портит символы
- .ps1 и .bat писать только ASCII (PowerShell 5.1 читает файлы без BOM
  как ANSI)
- Пути в скриптах и командах всегда в кавычках — проект может лежать в
  папке с пробелом (сейчас C:\Claude Projects\...)
- Долгие фоновые прогоны (от ~4-5 минут) — не молчать до готового
  результата: короткий статус раз в 1-2 минуты («прогон 2/4 на Sintel,
  входящие выключены, идёт 90 с»), чтобы было видно, что процесс не
  завис, а работает
- GUI-тесты: фоновую работу (сеть, yt-dlp) ждать через
  app.processEvents() + time.sleep(), НЕ QTest.qWait — он не отпускает
  GIL, фоновый Python-поток голодает (анализ страницы: qWait — нет ответа
  60 с, sleep/app.exec — 1.5 с; одинаково до и после правок 16.09.2026).
  В тесте не оставлять работающих QThread к выходу (cancel + wait) и
  отключать сетевую автопроверку обновлений (check_updates=False)
- У бесплатной модели GLM лимит 8 запросов в минуту. Не делай
  много мелких шагов подряд: объединяй проверки в один скрипт
  или одну команду, не запускай по отдельному вызову на каждый
  файл. При ошибке лимита — подождать минуту и повторить,
  не повторять сразу
