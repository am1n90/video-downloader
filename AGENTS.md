# Video Downloader — память проекта

Прочитай этот файл перед началом работы. Здесь всё состояние проекта.

## Что это

Десктопный загрузчик видео/аудио (YouTube, VK, TikTok и др.): Fluent Design,
очередь с паузой/докачкой, библиотека, автообновление через GitHub Releases.
С 15.09.2026 идёт большая задача «Торрент-стриминг» (раздел ниже).
Пользователь — владелец репозитория am1n90. Язык общения — русский.

### Состояние репозитория

- 17.09.2026: `origin/main` = `2c20479` (сессии 2.1-2.3). Часть A сессии
  2.4 — коммит `e85a7bd`; push владелец делает `sync.bat`.
  17.09 утром в `sync.bat` исправлен дефект: он смотрел только
  `git status --porcelain` и на чистом дереве печатал «Nothing to
  sync», хотя впереди `origin/main` стоял готовый коммит (push
  приходилось делать руками). Теперь два вопроса порознь: грязное
  дерево -> commit, `git rev-list origin/main..HEAD --count` > 0 ->
  push; «нечего синхронизировать» — только когда верно ни то, ни
  другое. Проверено на одноразовом репозитории со своим bare-origin:
  чисто+ahead 0, чисто+ahead 2, грязное, грязное+ahead, отсутствующий
  `origin/main`. ВНИМАНИЕ: 16.09.2026 в проекте работали ДВЕ сессии
  сразу; `sync.bat` коммитит всё дерево целиком, поэтому при
  параллельной работе он может увезти чужие недописанные правки (так и
  случилось с `90f4abc`).
- Коммиты задачи по порядку: `e73a61e` (план + сборка на 3.13),
  `0d942da` (код прототипа 0.1), `0496756` (код прототипа 0.2),

    движок один на процесс.
53. **Приоритет 0 у файла с данными + удаление = ошибка раздачи.** При

54. **Приоритеты нельзя применять, пока едет `move_storage`.** Поднятый

    «file too short»`, раздача в ошибке, приоритеты не применились.
    Поэтому `make_permanent(tid, save_path, priorities)` применяет
    галочки только по `storage_moved_alert`.

56. **Опрос раз в секунду не ловит конец очень короткого показа.**

### Долг 1.4: Библиотека торрентов — сделано (17.09.2026)

Владелец поменял план релиза 1.1.0: пункт «Библиотека» в режиме Torrent
не скрываем, а делаем настоящим разделом. План согласован до кода,
решение по удалению — владельцем (ниже).

1. **Хранилище — своя история в `settings.json` (`torrent_history`), а
   не список раздач движка.** Причины: «Очистить данные библиотеки»
   не должен трогать раздачи; раздача, снятая с карточки БЕЗ удаления
   файлов, должна остаться в Библиотеке (фильм скачан); дату и «какие
   файлы скачаны целиком» после снятия раздачи движок уже не знает.
   Живое состояние (качается, раздаётся, проценты) подмешивается из
   движка. Механизм тот же, что у истории видео: `_add_record` /
   `_remove_records` под общим `_lock`, дедуп при `load` по id.
2. **Запись:** `{id, name, save_path, added, files: [[путь, размер]],
   done: [номера файлов]}`. Появляется ТОЛЬКО после ответа «Скачать» или
   «Посмотреть» в окне выбора (`TorrentPage._remember`); после «Отмена»
   её нет. Поэтому после «Очистить» активные раздачи не всплывают
   обратно: `_sync_record` обновляет только существующие записи.
   `added` — `added_time` libtorrent (новое поле `TorrentItem`, хранится
   в fastresume). `done` — по `file_progress`, НЕ по размеру файла на
   диске: libtorrent создаёт файлы сразу полного размера. Пишется при
   каждом снимке движка, но `settings.json` сохраняется только при
   изменении.
3. **Удаление записи ВСЕГДА снимает раздачу с «Торрентов»** (решение
   владельца 17.09.2026, второй галочки «только из списка» не будет);
   галочка решает только судьбу файлов. Раздача в движке —
   `engine.remove(delete_files=…)`, он же убирает `.fastresume`,
   `.chosen`, `.pending`, `.parts`. Найдено при разборе: `remove()` при
   НЕ запущенном движке выходит раньше, чем удаляет эти файлы, —
   поэтому Библиотека в `showEvent` и перед удалением зовёт
   `start_engine()`, а если движок не поднялся, не удаляет вовсе.
   Раздачи в движке нет (сняли с карточки без файлов) — с галочкой
   файлы записи удаляет `remove_record_files`: ровно файлы записи,
   `.parts` и опустевшие папки ВНУТРИ папки сохранения; пути за её
   пределами пропускает. Занятый файл — запись остаётся, имя в InfoBar.
4. **Карточка «Торренты»:** «Удалить» без файлов — запись остаётся
   («Убрана из Торрентов»), перед снятием дописывается `done`; с
   файлами — запись убирается. «Отмена» в окне выбора тоже убирает
   запись (файлы удалены).
5. **Частичный приоритет (2.5/2.6).** Процент раздачи в Библиотеке НЕ
   показываем: после `focus_file` libtorrent считает раздачу по одной
   серии, и сериал выглядел бы «100%, Раздаётся». Считаем по видео:
   «Скачано 1 из 5 видеофайлов», размер «2 МБ из 3 МБ», у серий —
   «Скачано» / «37%» / «Не скачано (22%)»; раздача без раздачи —
   «Выбранное скачано», а не «Готово». Фильтр «Показать»: Скачано / Не
   докачано / Убраны из Торрентов.
6. **Открыть:** скачанный целиком файл — «Открыть» системным плеером
   (как в Библиотеке видео); недокачанный, раздача в движке —
   «Смотреть» через `TorrentPage.watch(tid, index)` (поток +
   `focus_file`); идущий просмотр — «Остановить просмотр». У сериала
   файлы под «Показать файлы», у фильма кнопки прямо в строке.
7. **Лимит записи (после ревью, 17.09.2026).** Раздача с сотнями файлов
   не должна раздувать `settings.json`: `library_record` хранит пути
   только первых `LIBRARY_FILES_MAX` (50) файлов, дальше — только
   счётчик и сумма размера (`files_more`/`files_more_size`); `done`
   обрезается тем же порогом и в `_sync_record`. Общий размер и «+N
   файлов» в подписи учитывают скрытый хвост, но его готовность не
   отслеживается (не входит в «Скачано X из Y» и категорию
   Скачано/Не докачано). Ограничение: видео за пределами первых 50
   файлов раздачи не получит кнопку «Смотреть»/«Открыть» — для реальных
   раздач видео почти всегда в начале списка.
8. **Проверено:** `test_torrent_gui.py` сценарий 14 (50 проверок на

   «Video Downloader» | «Torrent», при смене режима меняется весь

     (qfluentwidgets) в titleBar.hBoxLayout после titleLabel
   - все страницы обоих режимов добавляются в stackedWidget один раз

     пункты чужого режима скрываются
     navigationInterface.widget(routeKey).setVisible(...), переход на
     последнюю страницу режима, история qrouter очищается (кнопка
     «Назад» не уводит в скрытый режим)
   - settings["app_mode"] ("video" по умолчанию; новый ключ в DEFAULTS

   - DownloadManager и торрент-движок живут на уровне окна — загрузки
     одного режима идут, пока открыт другой
   - **одна общая страница «Настройки»** (внизу, в обоих режимах) с

     downloader.py не трогается
   - отклонены: removeInterface/addSubInterface при каждой смене

## Правила работы

- Работать только внутри папки проекта. Вне её разрешено только:
  %LOCALAPPDATA%\VideoDownloader и %LOCALAPPDATA%\Programs\
  VideoDownloader (с backup перед изменением) и %TEMP% (удалять после
  себя). Любое другое место на диске — сначала спросить владельца.
  Разрешено дополнительно (15.09.2026): %LOCALAPPDATA%\Programs\
  Python\Python313 (установка Python 3.13 для сборки)
- НИЧЕГО не публиковать на GitHub (push, release) без явного
  подтверждения владельца
- downloader.py (логика загрузок) не трогать без явной задачи владельца
- Новые зависимости: только stdlib в рантайме; сборочные — в
  requirements-dev.txt. Согласованные исключения: curl_cffi (1.0.4),
  libtorrent (торрент-стриминг, 15.09.2026)
- Bump версии = правка APP_VERSION в config.py (одно место), build.bat
  разнесёт в installer.iss (set_version.ps1) и latest.json
- settings.json — личные данные владельца: не коммитить, не пушить,
  не показывать содержимое
- SmartScreen-предупреждения при установке — ожидаемое поведение
  (нет кодовой подписи), это не баг
- Релизы: тег v<ver> строго равен APP_VERSION; порядок: коммит →
  push в main → gh release create v<ver> --target main; latest.json
  загружается вместе с установщиком
- Если задача неоднозначна — выбрать разумное допущение и явно
  написать его в отчёте; правила молча не придумывать
- В конце каждого отчёта — отдельный список «Что не проверено»
- Команды для этой машины — под фактическую оболочку терминала Cline
  (сейчас Git Bash/MINGW64; проверять uname -s), одной строкой; gh при
  необходимости по полному пути. Многострочный текст (коммиты, notes
  релиза) передавать файлом UTF-8 без BOM во временной папке вне
  репозитория
- Не ломай работающее: не переписывать несвязанный код, не создавать
  второй механизм там, где уже есть рабочий, сохранять совместимость
  settings.json и истории загрузок
- Ищи корневую причину проблемы: изучить текущую реализацию и поток
  данных; временные обходы без понимания причины не допускаются
- Файлы писать только инструментом редактирования, не через echo/Python
  в bash — экранирование портит символы
- .ps1 и .bat писать только ASCII (PowerShell 5.1 читает файлы без BOM
  как ANSI)
- Пути в скриптах и командах всегда в кавычках — проект может лежать в
  папке с пробелом (сейчас C:\Claude Projects\...)
- Долгие фоновые прогоны (от ~4-5 минут) — не молчать до готового
  результата: короткий статус раз в 1-2 минуты («прогон 2/4 на Sintel,
  входящие выключены, идёт 90 с»), чтобы было видно, что процесс не
  завис, а работает
- GUI-тесты: фоновую работу (сеть, yt-dlp) ждать через
  app.processEvents() + time.sleep(), НЕ QTest.qWait — он не отпускает
  GIL, фоновый Python-поток голодает (анализ страницы: qWait — нет ответа
  60 с, sleep/app.exec — 1.5 с; одинаково до и после правок 16.09.2026).
  В тесте не оставлять работающих QThread к выходу (cancel + wait) и
  отключать сетевую автопроверку обновлений (check_updates=False)
- У бесплатной модели GLM лимит 8 запросов в минуту. Не делай
  много мелких шагов подряд: объединяй проверки в один скрипт
  или одну команду, не запускай по отдельному вызову на каждый
  файл. При ошибке лимита — подождать минуту и повторить,
  не повторять сразу
